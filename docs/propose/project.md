# Swax — техническое задание

## Обзор

Swax — это CLI-утилита, которая строит и поддерживает граф зависимостей API на основе спецификаций Swagger и OpenAPI.
Она помогает командам QA и разработки понимать влияние изменений API до развертывания и составлять планы на тестирование изменений.

Основная идея — не анализировать тесты или код, а понять:

> «Если изменится этот endpoint, какие другие эндпоинты могут быть затронуты?»

---

## Цель

Создать минимальную, но мощную систему, которая отвечает на вопрос:

> «Какие части системы затрагиваются при изменении API и сгенерировать базовый план тестирования?»

---

## Основная концепция

Система строит **граф отслеживаемости (traceability graph)**:

```yaml
/payment:
  - /users
  - /orders

/orders:
  - /payment
```

- Узлы = пути API
- Рёбра = выявленные зависимости между эндпоинтами
- Зависимости означают: изменения в одном эндпоинте могут повлиять на другие

---

## Команды CLI

### 1. init

Инициализирует проект и загружает спецификации OpenAPI из репозитория.

#### Поведение:
- Создаёт каталог `.swax/`
- Спрашивает пользователя URL репозитория с которым будем работать
- Где в репозитории лежит спецификация
- Куда локально в проект загружать спецификации из удаленного репозитория
- Сохраняет конфигурацию в `.swax/config.yml`
- Клонирует репозиторий в tmp
- Загружает спецификации Swagger и/или OpenAPI в указанный в конфигурации каталог

#### Структура на файловой системе:
```
.swax/
├── config.yml
└── traceability.yml
<specs>/<path>/<from>/<config>
```

### Конфигурация

**Файл конфигурации**

```yaml
git:
  url: <repo URL>
  location: <path to specs in repo>

specs:
  type: <swagger | openapi>
  location: <download path>
```

**Переменные окружения**

Все переменные окружения должны начинаться с префикса `SWAX_`.
Приложение должно поддерживать .env файл по умолчанию.

Переменные для настройки:
- SWAX_LLM_PROTOCOL: anthropic, openai
- SWAX_LLM_BASE_URL: URL **БЕЗ** указания версии (например: `/v1)`, только базовый путь к API (https://host.com/api)
- SWAX_LLM_TOKEN: токен доступа к LLM API

**Опции командной строки**

- `--env-file <path>` базово при вызове приложения `swax --env-file .env <command>`

---

### 2. discover

Полное перестроение графа отслеживаемости с нуля.

#### Поведение:
- Разбирает все спецификации OpenAPI
- Извлекает все пути
- Отправляет эндпоинты в LLM (Anthropic)
- На основании анализа LLM просит схемы endpoints для сомнительных связей для уточнения контекста
- Связи после уточнения список endpoints окончательно формируется и отправляется с доп контекстом для составления графа зависимостей

#### Важно:
- Игнорирует существующую отслеживаемость
- Всегда создаёт свежий граф

#### Пример вывода для `.swax/traceability.yml`:
```yaml
/payment:
  - /users
  - /orders

/orders:
  - /payment
```

---

### 3. plan

Анализирует различия между базовой и текущей спецификациями и формирует отчёт о влиянии.
Для этого клонирует репозиторий в tmp и сравнивает спецификации.

#### Шаги:
1. Вычислить diff Swagger/OpenAPI:
   - добавленные эндпоинты
   - изменённые эндпоинты
   - удалённые эндпоинты
2. Отобразить изменения на граф отслеживаемости
3. Определить затронутые эндпоинты
4. Сформировать план воздействия на тесты с помощью LLM

#### Пример вывода:
```
# Impact Report

Summary: <short summary about changes>
Risk: <HIGH|MEDIUM|LOW>

## Modified

### /payment
<what changed>

## Affected

### /users
<how affected>

### /orders
<how affected>

Requirements:
- <gray zones or need to constrain>

Checklist:
- <what need verify>
```

---

### 4. update

Синхронизирует базовые спецификации и инкрементально обновляет отслеживаемость.

#### Поведение:
- Получает последние спецификации из репозитория
- Вычисляет diff относительно текущего базового состояния
- Обновляет только затронутые узлы в графе отслеживаемости
- Удаляет удалённые эндпоинты
- Добавляет новые зависимости через инференс LLM

#### Ключевое свойство:
- НЕ перестраивает граф целиком
- Обновляет только затронутые части

#### Пример вывода:
```
Update completed

+ /refund
~ /payment
- /legacy

Traceability updated:
+ 4 relations
~ 2 relations
- 1 relation
```

## Архитектурные правила

### 1. Уровень CLI
- Фреймворк: Click
- Никаких Typer, никаких FastAPI

### 2. Уровень LLM
- Провайдер: только OpenAI, Anthropic API
- Используется только в:
  - discover
  - update (инкрементальный инференс)

### 3. Модель отслеживаемости
- Только пути API (без HTTP-методов)
- Без абстракции ресурсов
- Без анализа на уровне схем

### 4. Область OpenAPI
- Swagger и OpenAPI 3.x
- Схемы запросов/ответов только для уточнения контекста LLM

### 5. Хранение
- Только YAML-файлы
- Без базы данных
- Без векторного хранилища
- Без отслеживания истории

---

## Архитектурные уровни

### Уровень Swagger/OpenAPI
- Разбор
- Валидация
- Вычисление diff

### Уровень отслеживаемости
- Хранение графа
- Сохранение
- Инкрементальные обновления

### Уровень обнаружения
- Вывод зависимостей на основе LLM

### Уровень планирования
- Анализ влияния
- Отчётность

---

## Основные принципы проектирования

1. **Разделение ответственности**
   - discover = полная перестройка
   - update = инкрементальная синхронизация

2. **Детерминированное хранение**
   - отслеживаемость всегда основана на YAML

3. **Минимальная абстракция**
   - только пути, без методов и ресурсов

4. **LLM — это не логика**
   - LLM только предлагает связи

CLI команды — точки входа, логика приложения отделена.
