# Swax: Базовая архитектура + init + discover

## Current State

Проект Swax — это CLI-утилита для построения графа отслеживаемости API на основе спецификаций OpenAPI/Swagger. Полное ТЗ описано в `docs/propose/project.md`.

Текущее состояние репозитория:
- `swax/` — пустой модуль (кода нет)
- `pyproject.toml` — настроен: Python 3.10+, ruff, pytest, setuptools-scm
- `.goga/` — инфраструктура готова: conventions.md (Python-правила), созданы 7 usage-файлов в `cooks/`
- `mkdocs.yml` — настроена документация
- `docs/propose/project.md` — полное ТЗ продукта

Отсутствуют:
- Точка входа CLI
- Парсер спецификаций OpenAPI/Swagger
- Интеграция с LLM (Anthropic, OpenAI)
- Работа с git-репозиторием
- Модели графа отслеживаемости
- Команды `init` и `discover`

## Description

Реализовать фундамент проекта Swax: каркас CLI, инфраструктурные пакеты (config, fs, git, llm), доменные пакеты (openapi, traceability), и две CLI-команды — `init` и `discover`. После выполнения задачи пользователь сможет:

1. Инициализировать проект Swax: указать git-репозиторий со спецификациями, путь к спекам в репозитории и локальный путь для их сохранения
2. Построить граф отслеживаемости с нуля через LLM-анализ эндпоинтов и их схем

Команда `init` интерактивно опрашивает пользователя, клонирует репозиторий во временный каталог, копирует спецификации в локальный каталог, сохраняет конфигурацию в `.swax/config.yml`. Команда `discover` парсит все спецификации, извлекает пути, отправляет их в LLM для построения графа, при необходимости запрашивает схемы для уточнения связей, и сохраняет результат в `.swax/traceability.yml`.

## Scope

**In scope:**
- Точка входа CLI (`swax`) с опцией `--env-file`, группой команд `init` и `discover`
- Пакет `config/`: загрузка `.swax/config.yml`, чтение `SWAX_*` переменных окружения, поддержка `.env` через python-dotenv
- Пакет `fs/`: создание/чтение каталога `.swax/`, копирование спецификаций из временного каталога в локальный путь
- Пакет `git/`: клонирование репозитория во временный каталог через GitPython, безопасная очистка
- Пакет `llm/`: адаптеры Anthropic и OpenAI с общим протоколом, фабрика по `SWAX_LLM_PROTOCOL`, промпты для построения графа и уточнения схем
- Пакет `domain/openapi/`: разбор и валидация Swagger 2.0 и OpenAPI 3.x через Prance, извлечение путей и схем
- Пакет `domain/traceability/`: модель графа отслеживаемости (только пути, без HTTP-методов), сохранение/чтение YAML
- Команда `init`: интерактивный опрос → запись `config.yml` → клонирование → копирование спецификаций
- Команда `discover`: парсинг всех спецификаций → извлечение путей → первый проход LLM для зависимостей → запрос схем для сомнительных связей → финальная сборка графа → запись `traceability.yml`
- Структура тестов, зеркальная структуре исходников
- Зависимости в `pyproject.toml`

**Out of scope (отложено в задачи 2 и 3):**
- Команда `plan` (diff спецификаций, отчёт о влиянии, тест-план через LLM)
- Команда `update` (инкрементальная синхронизация графа)
- Вычисление diff между базовой и текущей спецификациями
- Инкрементальное обновление графа
- Интеграция с LLM для генерации тест-плана

## Acceptance Criteria

- `swax --help` показывает справку по всем командам
- `swax init` интерактивно опрашивает URL репозитория, путь к спекам, путь загрузки; создаёт `.swax/config.yml`; клонирует репозиторий; копирует спецификации в указанный путь
- `swax --env-file .env discover` парсит все спецификации, строит граф отслеживаемости, сохраняет в `.swax/traceability.yml` в формате YAML (ключи — пути, значения — списки зависимых путей)
- Поддерживаются оба провайдера LLM через `SWAX_LLM_PROTOCOL` (`anthropic`, `openai`); переключение не требует изменения кода
- `SWAX_LLM_BASE_URL` передаётся без версионного сегмента (`/v1`), SDK добавляет его автоматически
- Валидация: при отсутствии `SWAX_LLM_TOKEN`, некорректном `SWAX_LLM_PROTOCOL` или base URL с `/v1` — осмысленные ошибки доменного уровня
- Парсинг спецификаций работает и для Swagger 2.0, и для OpenAPI 3.x (через Prance, с развертыванием `$ref`)
- Граф отслеживаемости содержит только пути (без HTTP-методов), без дубликатов рёбер
- Все публичные функции и классы имеют docstrings в Google-стиле (согласно conventions)
- Тесты покрывают основные сценарии `init` и `discover`, edge-cases, интеграцию пакетов
- `pytest tests/ -x` проходит, `ruff check swax/` без ошибок

## Risks and Constraints

- **Качество вывода LLM** — LLM может возвращать некорректный JSON или галлюцинировать связи. Требуется строгая парсинг-защита и валидация структуры ответа (см. `anthropic.md` / `openai.md`)
- **Стоимость вызовов LLM** — `discover` с большим количеством эндпоинтов может потребовать много токенов. Ограничение `max_tokens` и чёткие промпты обязательны
- **Разрешение `$ref` в спецификациях** — Prance разворачивает ссылки в памяти, что может потребовать много RAM для очень больших спецификаций. Принять как известное ограничение
- **Временный каталог git** — клонирование создаёт временные файлы; cleanup обязателен даже при ошибке (см. `gitpython.md`)
- **Безопасность токенов** — переменная `SWAX_LLM_TOKEN` не должна логироваться (см. conventions — Log Content Restrictions)
- **Python 3.10+** — синтаксис `kw_only=True` для dataclass-полей недоступен (только для классов данных); pydantic-модели используют `Optional[...]` явно

## Scope Estimate

**Задача 1 (текущая) — большая, но цельная.** Внутренняя декомпозиция не требуется: `init` и `discover` тесно связаны (init готовит структуру, discover её использует) и не дают самостоятельной ценности по отдельности.

Задача входит в общую декомпозицию продукта Swax на 3 подзадачи:
- **Задача 1 (эта)** — базовая архитектура + init + discover
- **Задача 2 (позже)** — команда plan
- **Задача 3 (позже)** — команда update

## Existing Architecture

Архитектура ещё не существует. Задача создаёт её с нуля. Запланированная структура пакетов:

```
swax/
├── __init__.py
├── __main__.py            # точка входа для python -m swax
├── cli/
│   ├── __init__.py
│   ├── __main__.py        # определение Click-группы main
│   ├── init.py            # команда init
│   └── discover.py        # команда discover
├── config/
│   ├── __init__.py
│   ├── env.py             # SWAX_* переменные, .env загрузка
│   └── settings.py        # модели pydantic для config.yml
├── domain/
│   ├── __init__.py
│   ├── openapi/
│   │   ├── __init__.py
│   │   ├── parser.py      # Prance-разбор
│   │   └── paths.py       # извлечение путей и схем
│   └── traceability/
│       ├── __init__.py
│       ├── graph.py       # модель графа
│       └── storage.py     # YAML I/O
├── fs/
│   ├── __init__.py
│   └── project.py         # операции с .swax/, копирование спецификаций
├── git/
│   ├── __init__.py
│   └── clone.py           # GitPython-клонирование
└── llm/
    ├── __init__.py
    ├── client.py          # общий протокол, фабрика
    ├── anthropic_adapter.py
    ├── openai_adapter.py
    └── prompts.py         # системные промпты для discover
```

Структура тестов зеркалит исходники (согласно conventions): `tests/cli/test_init.py`, `tests/domain/openapi/test_parser.py` и т.д.
