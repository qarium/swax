# Swax: Команда update

## Current State

Эта задача — завершающая в декомпозиции продукта Swax. После Задач 1 и 2 у Swax есть:

- Команды `init`, `discover`, `plan`
- Граф отслеживаемости в `.swax/traceability.yml`
- Локальный каталог базовых спецификаций (из `init`)
- Парсер Prance с разворачиванием `$ref`
- Подсистема diff через `deepdiff` (`domain/openapi/diff/`)
- LLM-клиент с двухитерационным паттерном: предложение → уточнение схемами → финал (используется в `discover`)
- Механизм клонирования репозитория во временный каталог

Отсутствует:
- Команда `update`
- Механизм инкрементального обновления графа (без полного перестроения)
- Замена локальных базовых спецификаций свежими из репо
- LLM-промпт для инкрементального инференса (с учётом существующего графа)

## Description

Реализовать команду `update`, которая синхронизирует локальное состояние с репозиторием и инкрементально обновляет граф отслеживаемости без полного перестроения.

Отличие от `discover`: `discover` игнорирует существующий граф и строит его с нуля. `update` использует существующий граф как контекст и перестраивает его с учётом дельты эндпоинтов.

Логика команды:
1. Клонировать репозиторий во временный каталог (через `git/`)
2. Парсинг свежих спецификаций через Prance (через `domain/openapi/`)
3. Парсинг локальных базовых спецификаций
4. Diff между базовой и текущей спецификациями (через `domain/openapi/diff/`) → added/modified/removed эндпоинты
5. Если diff пустой — вывести "Already up to date", завершить
6. Двухитерационный LLM-вызов:
   - **Итерация 1**: отправить текущий граф + дельту эндпоинтов → получить предложенный граф + список сомнительных связей
   - **Итерация 2**: отправить запрошенные схемы для помеченных связей → получить финальный граф
7. Заменить локальные базовые спецификации свежими из репозитория (полная замена файлов)
8. Сохранить финальный граф в `.swax/traceability.yml`
9. Вывести сводку изменений

Двухитерационный паттерн полностью переиспользует инфраструктуру `discover` из Задачи 1 (тот же LLM-клиент, тот же механизм запроса схем). Различие — в системном промпте: вместо «построй граф с нуля по этим эндпоинтам» — «вот существующий граф, вот дельта эндпоинтов, перестрой граф с учётом нового контекста».

## Scope

**In scope:**
- Команда `update` (CLI handler в `cli/update.py`)
- LLM-промпт для инкрементального инференса (новый раздел в `llm/prompts.py`): системный промпт + формат пользовательского payload (существующий граф + дельта + опционально схемы)
- Пакет `domain/traceability/increment.py`: вычисление дельты рёбер (added/modified/removed) между старым и новым графом для сводки
- Пакет `fs/specs_sync.py`: синхронизация локального каталога спецификаций (полная замена файлов свежими из временного каталога)
- Модели pydantic для дельты графа (endpoint diff + edge diff)
- Вывод сводки в stdout:
  ```
  Update completed

  + /refund
  ~ /payment
  - /legacy

  Traceability updated:
  + 4 relations
  ~ 2 relations
  - 1 relation
  ```
- Тесты, зеркальные структуре исходников

**Out of scope:**
- Сохранение истории обновлений (каждое обновление перезаписывает состояние)
- Команда `discover` — уже реализована в Задаче 1
- Подсистема diff — уже реализована в Задаче 2
- Команда `plan` — уже реализована в Задаче 2
- Альтернативные стратегии инкрементального обновления (k-hop окрестности, переоценка только существующих рёбер) — не нужны, используется единый двухитерационный подход

## Acceptance Criteria

- `swax update` клонирует репозиторий, сравнивает спеки с локальными, перестраивает граф, заменяет локальные спеки
- Diff корректно идентифицирует добавленные/изменённые/удалённые эндпоинты (использует подсистему из Задачи 2)
- При отсутствии изменений выводит "Already up to date" и завершает без LLM-вызова
- При наличии изменений выполняет двухитерационный LLM-вызов: предложение → уточнение схемами → финал
- LLM-контент: текущий граф + дельта эндпоинтов (added/modified/removed); формат промпта оптимизирован под инкрементальный сценарий
- Локальные спецификации полностью заменяются свежими из репо (старые файлы удаляются, новые/изменённые копируются)
- Граф сохраняется в `.swax/traceability.yml` в том же формате, что и после `discover`
- Вывод сводки соответствует шаблону ТЗ: `+ / ~ / -` для эндпоинтов и рёбер
- При отсутствии графа (`.swax/traceability.yml` не существует) — осмысленная ошибка с подсказкой запустить `discover`
- Все публичные функции и классы имеют docstrings в Google-стиле (согласно conventions)
- Тесты покрывают: вычисление дельты графа, синхронизацию спек, edge-cases (нет изменений, нет графа, пустая дельта), двухитерационный паттерн
- `pytest tests/ -x` проходит, `ruff check swax/` без ошибок

## Risks and Constraints

- **Качество инкрементального инференса** — LLM получает существующий граф как контекст. Если граф содержит ошибки (галлюцинации из предыдущего `discover`/`update`), они могут закрепиться. Подсказка: периодически запускать `discover` для полной перестройки
- **Стоимость LLM** — `update` отправляет весь текущий граф + дельту. Для крупных графов payload может быть большим. Чёткие промпты и `max_tokens` обязательны
- **Согласованность дельты эндпоинтов и рёбер** — после LLM-ответа нужно вычислить diff рёбер (что добавилось, что изменилось, что удалилось). Операция сравнения множеств рёбер тривиальна, но должна быть покрыта тестами
- **Атомарность операции** — замена спецификаций + сохранение графа должны быть атомарны: при ошибке LLM локальные спеки не должны заменяться (текущее состояние сохраняется для повторного запуска). Порядок: сначала LLM → потом замена спек → потом сохранение графа
- **Race condition** — повторный `update` во время уже идущего может повредить состояние. Принять как известное ограничение (файл-блокировка не требуется на данном этапе)
- **Производительность deepdiff** — для крупных спецификаций требуются `cutoff`-опции (см. `deepdiff.md`)
- **Согласованность с `plan`** — `plan` видит diff до `update`, `update` применяет его. Если пользователь запускает `plan` после `update`, diff пустой, отчёт "No changes detected"

## Notes

- Обновление базовых спецификаций: **полная замена** локальных спек свежими из репо. Решение согласовано с пользователем
- Подход к инкрементальному обновлению: единый LLM-вызов с текущим графом + дельтой эндпоинтов (без разбиения на «затронутые/соседи/k-hop»). Решение согласовано с пользователем — первоначальная декомпозиция была overengineering
- Двухитерационный паттерн (предложение → уточнение схемами → финал) переиспользуется из `discover`. Контент LLM в Итерации 1 — весь текущий граф + дельта эндпоинтов; в Итерации 2 — запрошенные схемы. Решение согласовано с пользователем
- Атомарность: LLM → замена спек → сохранение графа. При ошибке на любом шаге локальное состояние не повреждается
- Сводка вывода следует шаблону ТЗ: `+ / ~ / -` для эндпоинтов и рёбер
- Usage-файлы не требуются — все зависимости покрыты в Задачах 1 и 2
